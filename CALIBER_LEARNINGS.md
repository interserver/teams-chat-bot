# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[env]** The global `~/.npmrc` on this dev machine sets `production=true`, which causes `npm install` to silently skip `devDependencies`. Symptoms: `eslint`, `@eslint/js`, `globals`, etc. never appear in `node_modules` even after a successful-looking install. Use `npm install --include=dev --legacy-peer-deps` (or `npm config set production false` locally) when devDependencies must be installed. Verify with `ls node_modules/@eslint/js` — not just exit code.
- **[gotcha]** When the Bash tool returns empty stdout/stderr (`{}`) from an `npx eslint ...` invocation, the most likely cause is a missing config-resolution dependency (eslint-config-standard, @eslint/js, etc.) not being installed because of `production=true` in npmrc — not a config syntax error. Run `npm ls <pkg>` and check `node_modules/` directly before rewriting the eslint config.
- **[gotcha]** The repo's `env/.env.local` is unused TeamsFX boilerplate. `server/index.js` only loads `../.env` via `dotenv.config({ path: ENV_FILE })`. The `env/` directory can be deleted without affecting runtime. Don't add new env files there.
- **[convention]** ESLint is now flat-config (`eslint.config.js`, ESLint 9). The legacy `.eslintrc.js` + `.eslintignore` pair was removed during the v8→v9 migration. Do NOT recreate `.eslintrc*` files; edit `eslint.config.js` only.
- **[pattern]** When adding a new command in `server/commands/*.js`: (1) gate admin-only commands with `if (ima !== 'admin') return null;` at the top of `match()`, (2) add the `require('./newCmd')` line to the array in `server/commands/index.js` — without that line the command never dispatches, (3) add a `describe('newCmd command', () => { ... })` block to `test/commands.test.js` covering each action path and the non-admin rejection (this is the project's de-facto test convention).
- **[pattern]** GitHub-API commands (`githubIssues.js`, `githubLabels.js`) lazy-initialize Octokit via a `getOctokit()` function so that `process.env.GITHUB_TOKEN` is read at first use, not at module load. New external-API integrations should follow this pattern so missing env vars don't crash startup.
- **[gotcha]** When adding a new package that pulls in eslint-9 peer-deps (e.g. `@eslint/js@^10`), `npm install` fails with ERESOLVE against the older `eslint-plugin-*` siblings still in `devDependencies`. Use `--legacy-peer-deps`. The old `eslint-plugin-standard`, `eslint-plugin-node`, `eslint-config-standard` entries in `package.json` are legacy and can be removed, but only do so when explicitly cleaning up.
- **[gotcha]** Any JS regex character class containing multi-code-point emoji MUST use the `u` flag. Without it, JS treats the pattern as UTF-16 code units and surrogate halves match across unrelated emoji that share a high surrogate. Concrete trap: `/^[⏳🔄✅❌⏭️⚠️ℹ️❓]/` (no `u`) falsely matches text starting with 📦 because 📦 (U+1F4E6) and 🔄 (U+1F504) share the D83D high surrogate. This caused the notification consumer to misclassify a push-header message as a job-status line and produce duplicated `header + — jobs — + header` output. Always write `/^[…emoji…]/u` and add a regression test that includes the lookalike emoji you do NOT want to match.
- **[pattern]** In `server/queue/notificationConsumer.js`, the trackable-message merge logic is exposed as the pure `mergeGithubTrackable(existingText, env)` function and exported alongside `startConsumer`/`stopConsumer`/`runTick`. When changing how `header`/`— jobs —`/`jobList` are assembled, modify that function and extend `test/notificationConsumer.test.js` rather than editing the merge code inline in `tryEdit()` — the inline path was extracted specifically because it was untestable.
- **[gotcha]** The notification consumer's edit path is triggered by matching `extra._commit_sha` against `recent.commit_sha` for envelopes sharing the same `dedup_key` (auto-injected as `github:commit:{sha7}` for GitHub events). If a `push` event is enqueued twice for the same SHA within `NOTIF_EDIT_WINDOW_MS` (30 min default), the second call goes through `mergeGithubTrackable` rather than starting a new message. Any change to the parsing of `recent.text` must handle the case where `existingText` is itself a push message — do NOT treat unknown-format text as a job line by default, or duplicate pushes will produce `push + — jobs — + push` output.
- **[gotcha]** `npm test` runs `node --test 'test/*.test.js'` — files must literally match that glob to be picked up. The glob is single-quoted so the shell does NOT expand it; node's test runner expands it internally. A bare `node --test test/` (no glob) silently produces no output in this repo. Always invoke `npm test` or `node --test test/<file>.test.js` for new test files; verify your new file's tests appear in the output count, not just that the command exits 0.
