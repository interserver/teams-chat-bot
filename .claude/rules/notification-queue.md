# Notification Queue Rules

- Redis keys use prefix `process.env.NOTIF_KEY_PREFIX || 'notif:'`. Key helper: `k(name) => KEY_PREFIX + name`.
- Queue: `notif:queue` (LPUSH/BRPOPLPUSH). In-flight: `notif:processing`. Failed: `notif:dead` (with `_dead_reason`, `_dead_at`).
- Envelope JSON: `{ channel, text|attachments, extra?: { dedup_key, event_type, _commit_sha, data }, fallback_webhook_url? }`. `channel` MUST resolve via `CHANNELS`.
- Trackable mode: envelopes with `extra.dedup_key` edit the most recent activity within `NOTIF_EDIT_WINDOW_MS` (30 min). After 3 appends, summarize as `N updates · last HH:MM`.
- GitHub commit grouping: events carrying a commit SHA auto-get `dedup_key=github:commit:{sha7}`. Window: `NOTIF_COMMIT_GROUP_WINDOW_MS` (3 min).
- `renderTrackable()` collapses commit bullets into one comma-separated hash-link line via `collapseCommitBullets()` when count > `NOTIF_COMMIT_COLLAPSE_COUNT` (15) OR the expanded render exceeds `MAX_ACTIVITY_BYTES` — never let `guardActivity` tail-truncate the newest commits. Separately, `indentAsBullet()` collapses a NESTED push bullet's commit sub-bullets into one level-2 `Commits: [sha7](url), …` line when there are more than `NOTIF_NESTED_COMMIT_COLLAPSE_COUNT` (5).
- GitHub `release` stubs are rewritten in `attachPrContext` by `describeReleaseEvent(data, repo)` (returns `null` to keep the stub); pass payload text through `sanitizeReleaseTitle()` so it cannot unbalance `**bold**`/`[link](url)` markdown.
- GitHub `package`/`registry_package` stubs are rewritten by `describePackageEvent(data, repo)` (reads `registry_package`, legacy `package`; fail-soft to the stub when no usable package object). `normalizeGithubDedup` keys them on `github:package:{repo}:{name}:{version||latest}` — the bot-side key is authoritative over the producer's. `condensedBulletText` renders folded bullets as `📦 [**label**](url) — verb`. Labels/links come from `packageLabel()` (`name:tag` for containers, `name@sha256:<12hex>` for digest-only) and `packageUrl()` (prefers `package_version.html_url`; GitHub's top-level `https://github.com/{owner}/packages/{id}` 404s). `filters.js` silently drops untagged container versions (explicit empty `container_metadata.tag.name`).
- Container publishes tagged with a commit SHA (bare 7–40 hex, `sha-<hex>`, or a FULL 40-hex SHA with a variant affix like `<sha>-intel` — see `commitShaFromTag()`) are re-keyed by `attachPackageCommit()` (runs after `attachPrContext`) onto `github:commit:{sha7}` — ONLY when that trackable is live in the same room — so they nest as bullets under the commit that built them. Floating tags (`latest`) resolve via the same digest: same-tick pre-pass `collectTickPackageShas()`, then the `notif:pkgdigest:{name}:{digest}` index. `target_oid` is the package repo's HEAD, never use it for linking. GitHub delivers the per-tag events in no fixed order. An unlinked floating tag first tries `soleActiveCommit()`: the ONE commit with CI activity in the image's builder repo within `NOTIF_PKG_ACTIVE_CI_MS` (600000) that has a live trackable in the room (`source: 'active_ci'`). Builder repo = `notif:pkgrepo:{name}` (learned on SHA-tag links via `notif:sharepo:{sha7}`, seeded by `recordActiveWorkflow`) else the package's repo — images are filed under their source-label repo, not always their builder. Overlapping builds (≥2 candidates) never guess; the item is re-queued (`shouldDeferPackage()` → `deferPackageItem()`: LPUSH the ORIGINAL raw + `extra._pkg_defer_since`) for up to `NOTIF_PKG_DEFER_MS` (15000) until its SHA-tagged sibling seeds the digest index. Once the defer window is spent, `attachPackageSibling()` nests the still-unlinked tag (chiefly `buildcache*`, whose cache-manifest digest never matches) under the most recent live commit a SHA-tagged image of the same package linked to within `NOTIF_PKG_SIBLING_MS` (300000; `notif:pkgsha:{name}` sorted set, `source: 'recent_sibling'`). `packageLabel()` shortens full 40-hex SHAs in tags to 12 hex so `<sha>-intel`/`<sha>-latest` keep distinct labels — the label is the bullet identity. Traces: `package_commit_attached` / `package_commit_skipped` / `package_deferred`.
- PR-context attachment (`attachPrContext`): rewrites `dedup_key` to `github:pr:{repo}:{n}` for pushes/deletes/creates on a branch in `notif:prbranch:{repo}:{branch}` AND for `issue_comment` whose `issue.pull_request` is set OR `issue.html_url` matches `/pull/{n}`. Runs AFTER `normalizeGithubDedup` and BEFORE `isActionTriggeredPush`.
- Within a single tick, items sharing a `dedup_key` MUST be folded via `groupTrackableByDedup` → `canBatchMergeGroup` → `handleTrackableBatch` (1 API call) — NOT iterated sequentially.
- EVERY send/update MUST pass through `guardActivity(activity, room)` — Teams silently drops activities over `MAX_ACTIVITY_BYTES` (the `RestError` dies in `onTurnError`). It trims attachments via `fitAttachmentsActivity`, truncates text, downgrades to a text stub as a last resort, and emits an `oversized_guard` trace. It never throws.
- Oversized coalesced text is split with `splitTextIntoChunks(combined, MAX_ACTIVITY_BYTES, APPEND_BREAK)` and sent as ordered chunks inside one proactive turn; on partial failure use `countDeliveredItems` so `fallbackSend` never re-posts what already landed.
- Strip `TRUNCATION_MARKER` from stored `recent.text` with `stripTruncationMarker` before composing the next edit, so markers do not pile up across edit cycles.
- Filters (`server/queue/filters.js`): drop `star`/`watch`/`fork`/`ping`; drop successful `check_run`/`workflow_job`; drop `${{ matrix.* }}` placeholders. Use `LOW_SIGNAL_GITHUB_EVENTS`/`SUCCESSFUL_CHECK_CONCLUSIONS`/`SUCCESSFUL_WORKFLOW_CONCLUSIONS` sets.
- Announce redirect: `NOTIF_ANNOUNCE_REPOS` (comma-list of `owner/*` or `owner/repo`) → `int-dev-announce`; `NOTIF_ANNOUNCE_REPOS_EXCLUDE` exempts. Exclude wins. Use `decideAnnounceRedirect(repo, listRaw, excludeRaw)`.
- Metrics counters: increment `notif:metrics:{enqueued|sent|edited|coalesced|redirected|fallback|dead}` on the corresponding event.
- Recovery on startup: move `notif:processing` items back to `notif:queue`.
- Trace every decision via `trace.emit(kind, payload)` from `notifTrace.js` — match positive and negative branches (e.g. `announce_redirect` + `announce_excluded`).
- Test mock seam: `_setInternalsForTest({ redis, redisBot, adapter })` swaps module handles. Restore in `after()`.
